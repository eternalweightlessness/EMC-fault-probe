# ADR 0001：轻量 Runtime 与应用边界

- 状态：Accepted
- 日期：2026-08-24

## 背景

仓库已经通过新骨架实验验证了 Ollama native tool calling、Prompt 工具协议、
RAG 和多轮记忆。下一步需要把这些能力组成正规 Agent 应用，同时
避免在需求仍简单时引入成熟 harness 的复杂度。

## 决策

1. 继续使用项目自有 `LocalRuntime` 作为默认 runtime。
2. 业务层通过 `AgentRuntime` Protocol 依赖 runtime，不依赖具体框架。
3. Ollama、Chroma 和未来 harness 都放在 `integrations`。
4. FastAPI 后端作为桌面端和未来 Web 端的统一应用边界。
5. PyQt6 桌面端只通过 API 使用后端，不直接调用模型和数据库。
6. JSON/JSONL 继续作为当前规模的数据和会话存储，不提前引入关系数据库。
7. 每个独立板块使用直接基于 `main` 的分支和 PR；最后由集成分支完成装配。

## 原因

- 本地 runtime 足以覆盖当前单工具循环，代码量小且适合学习。
- Protocol 让后续成熟 harness 成为适配器替换，不影响核心业务与 UI。
- 前后端边界避免打包版与开发版形成两套业务代码。
- JSONL 追加写适合会话事件，崩溃时最多损坏最后一行，并能按事件追溯。

## 影响

正面影响：

- 模块职责可测试，实验脚本不再承担生产入口。
- 后端可独立热重载，桌面 UI 可独立调试。
- 接云端 API 或成熟 harness 时不改 HTTP 合约。

代价：

- 桌面版需要管理本地后端进程或连接地址。
- 在正式流式协议落地前，需要先定义稳定的事件模型。
- 堆叠 PR 必须按依赖顺序审查和合并。

## 被拒绝的方案

- **立即使用 LangGraph/LangChain**：当前只有单 loop 和少量工具，收益不足以抵消
  新抽象与调试成本。
- **桌面端直接调用 Ollama/Chroma**：实现快，但会复制编排逻辑并阻断未来 Web
  客户端复用。
- **一次性迁移所有模块的大 PR**：难以审查、回滚和定位回归，不符合本次开发
  规范要求。
